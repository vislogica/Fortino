# 🇬🇧 English

One folder per chapter of the book, for example `Ch07.BusinessLogic/`. Inside:

- `Vulnerable/` the vulnerable code;
- `Secure/` the fixed code;
- `Shared/` the parts that are the same in both versions (requests, queries, helpers): not code from the book;
- `Scenarios/` the Lab cases (classes implementing `ILabCase`). Each case describes its **manual trial**
  (`ManualTrial`): user, start page, steps, expected result, what it proves and where to put the
  breakpoint, for the vulnerable version and for the fixed one;
- `ChNNModule.cs` the chapter module (implements `ILabChapterModule`): it registers services, addresses
  and any data or files to prepare at every database reset.

## How a trial picks the version of the code
The addresses are the real ones of the application (for example `/orders/{id}/stato`), not separate Lab
addresses. When the reader presses **Inizia la prova** (start the trial), the `Fortino.Prova` cookie
remembers chapter, case and version. Then, depending on the chapter:

- the page or the action reads the cookie with `LabTrialState.VariantFor(chapter, case)` and calls the
  class in `Vulnerable/` or in `Secure/`;
- or the address is registered twice with `MapTrialVariant` (`Lab/TrialVariantRouting.cs`), once per
  version, and the one chosen by the cookie answers.

Outside a trial, the fixed version always answers.

## The code in the book
The pieces of code printed in the book are enclosed between `#region libro: name` and `#endregion`.
The Lab shows them on screen and the book script copies them into the text. The highlighted lines are
in `Lab/Highlights.json`, generated by the book script.

Rule: vulnerable code exists **only** in the `Vulnerable/` folders. The rest of the application is
written the correct way.

# 🇮🇹 Italiano

Una cartella per capitolo del libro, per esempio `Ch07.BusinessLogic/`. Dentro:

- `Vulnerable/` il codice vulnerabile;
- `Secure/` il codice corretto;
- `Shared/` il contorno uguale per le due versioni (richieste, letture, aiuti): non è codice del libro;
- `Scenarios/` i casi del Laboratorio (classi che implementano `ILabCase`). Ogni caso descrive la sua
  **prova a mano** (`ManualTrial`): utente, pagina di partenza, passi, risultato atteso, cosa dimostra e
  dove mettere il punto di interruzione, per la versione vulnerabile e per quella corretta;
- `ChNNModule.cs` il modulo del capitolo (implementa `ILabChapterModule`): registra servizi, indirizzi
  ed eventuali dati o file da preparare a ogni ripristino del database.

## Come la prova sceglie la versione del codice
Gli indirizzi sono quelli veri dell'applicazione (per esempio `/orders/{id}/stato`), non indirizzi
separati per il Laboratorio. Quando il lettore preme **Inizia la prova**, il cookie `Fortino.Prova`
ricorda capitolo, caso e versione. Poi, secondo il capitolo:

- la pagina o l'azione legge il cookie con `LabTrialState.VariantFor(capitolo, caso)` e chiama la classe
  di `Vulnerable/` o di `Secure/`;
- oppure l'indirizzo è registrato due volte con `MapTrialVariant` (`Lab/TrialVariantRouting.cs`), una per
  versione, e risponde quella scelta dal cookie.

Fuori da una prova risponde sempre la versione corretta.

## Il codice nel libro
I pezzi di codice stampati nel libro sono racchiusi tra `#region libro: nome` e `#endregion`.
Il Laboratorio li mostra a video e lo script del libro li copia nel testo. Le righe evidenziate stanno
in `Lab/Highlights.json`, generato dallo script del libro.

Regola: il codice vulnerabile esiste **solo** nelle cartelle `Vulnerable/`. Il resto
dell'applicazione è scritto nel modo corretto.
